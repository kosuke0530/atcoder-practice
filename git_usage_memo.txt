Gitの使い方メモ（AtCoder用）
========================================

このメモのコマンドは、ターミナルでAtCoderフォルダを開いて実行する。
ファイル名やコミットID、ブランチ名は、そのときの対象に置き換える。

1. いつもの3つの操作の意味
----------------------------------------
git add     ：次のコミットに含める変更を選ぶ（ステージング）。
git commit  ：選んだ変更を、自分のPC内の履歴に記録する。
git push    ：記録したコミットをGitHubなどのリモートへ送る。

編集 → addで選択 → commitで記録 → pushで共有・保管

・addだけでは履歴に残らない。
・commitだけではGitHubには送られない。
・pushしても、まだコミットしていない編集内容は送られない。
・addした後にさらに編集した部分は、もう一度addする必要がある。

2. 普段のおすすめ手順
----------------------------------------
例：EX2の解答を書いたとき

git status
  → 変更したファイル、追加予定の変更、未追跡ファイルを確認する。

git diff
  → 追跡済みファイルの、まだaddしていない変更を見る。
    新しく作った未追跡ファイルの中身はここには表示されない。

git add APG4bPython_ans/EX2.py
  → EX2.pyの変更を次のコミットに含める。

git diff --staged
  → add済みの変更、つまり次のコミットに入る内容を見る。

git commit -m "EX2の解答を追加"
  → 変更内容がわかる日本語で記録する。

git push
  → コミットをリモートへ送る。

git status
  → コミットし忘れた変更がないか確認する。

全部まとめて記録したい場合は、個別のaddの代わりに次を使う。

git add .

現在のフォルダ以下の追加・変更・削除をまとめて選ぶ。
関係のない変更まで含めていないか、statusとdiff --stagedで確認する。

3. コミットの区切り方
----------------------------------------
あとから見て「何をした記録か」がわかる単位にする。

例：
git commit -m "EX3の解答を追加"
git commit -m "EX4の境界値の処理を修正"
git commit -m "EX5の別解と計算量のメモを追加"

必ず1ファイルずつにする必要はない。
同じ目的の変更なら、複数ファイルをまとめてもよい。

4. 過去の履歴を見る
----------------------------------------
git log --oneline
  → コミットIDとメッセージを1行ずつ表示する。

git log --oneline -- APG4bPython_ans/EX2.py
  → EX2.pyに関係する履歴を見る。

git show HEAD
  → 最新のコミットの内容を見る。HEADは通常、現在の最新コミットを指す。

git show abc1234
  → 指定したコミットの変更を見る。
    abc1234は例。logに表示された実際のコミットIDに置き換える。

git show abc1234:APG4bPython_ans/EX2.py
  → そのコミット時点のEX2.pyの中身を見る。作業中のファイルは変わらない。

履歴や差分の画面から戻れない場合は、qを押す。

5. 別解をブランチで試す
----------------------------------------
ブランチは、元の履歴から分かれて変更を記録するためのもの。
フォルダをコピーせずに、AC済みの解答と試行中の別解を分けて扱える。

例：mainにAC済みの解答をコミットした後、EX2の別解を試す。
始める前にgit statusで確認し、残っている編集は先にコミットしておく。

git switch -c ex2-alternative
  → 現在のコミットから新しいブランチを作り、切り替える。

（EX2.pyを編集して、動作を確認する）

git add APG4bPython_ans/EX2.py
git commit -m "EX2を別の解法で実装"

git diff main...ex2-alternative -- APG4bPython_ans/EX2.py
  → 分岐点から別解ブランチで加えた変更を見る。

git switch main
  → mainに戻る。作業フォルダのファイルもmainの内容に切り替わる。

別解をmainに取り込みたい場合：

git merge ex2-alternative
git push

別解を取り込まず残しておきたい場合：
  → mergeせず、そのブランチを残す。再開時は次を使う。
git switch ex2-alternative

別解ブランチもGitHubに送っておきたい場合：
git push -u origin ex2-alternative
  → 初回に送信先との対応を設定する。
    以降、そのブランチ上では通常git pushだけで送れる。

補足：mainと別解で同じ箇所を別々に変更すると、merge時に競合することがある。
その場合はgit statusで対象を確認し、ファイル内の競合箇所を修正してから
git addとgit commitで確定する。取り込みを中止するならgit merge --abort。

6. addを取り消す・変更を取り消す
----------------------------------------
addの選択だけを取り消したい場合：

git restore --staged APG4bPython_ans/EX2.py
  → ステージングから外す。ファイルの編集内容は残る。

まだaddしていない編集を破棄したい場合：

git restore APG4bPython_ans/EX2.py
  → 作業ファイルをステージング側の内容に戻す。
    add済みの変更がなければ、最新コミットの内容に戻る。
    破棄した未記録の編集はGitでは通常戻せないので、先にdiffで確認する。

コミット済みの変更を取り消したい場合：

git revert abc1234
  → 指定コミットの変更を打ち消す、新しいコミットを作る。
    元のコミットは履歴に残る。push済みの変更にも使える。
    メッセージ編集画面が開いたら、取り消す理由を日本語で記入する。

7. 別のPCやGitHubで加えた変更を取り込む
----------------------------------------
作業中の変更を先にコミットし、取り込みたいブランチで実行する。

git pull --ff-only
  → リモートの更新を取得し、履歴が分岐していなければ取り込む。
    手元とリモートの両方に独自のコミットがあると停止する。

停止したら、次で履歴の分岐を確認してから統合方法を考える。

git log --oneline --graph --all

8. 最初に覚える順番
----------------------------------------
まず：status / diff / diff --staged
次に：log / show
別解を試したくなったら：switch / merge
必要になったら：restore / revert / pull

AtCoderの記録だけでも、変更の確認・履歴の参照・別解の比較は練習できる。
毎回すべてのコマンドを使う必要はない。
